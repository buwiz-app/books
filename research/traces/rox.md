### 7. SDK contract (`server/sdk/mini-app` and broker)

- **Plugin shape:** a stdio MCP server only (`plugins.mjs` `spawnSpec` L59–73 refuses url and non-stdio transports; spec Q4). Reserved tools: `rox.provision`, `rox.session.open`, `rox.session.close`, `rox.ticket.resolve`, `rox.uninstall` (`docs/bridge.md`, "Reserved tools").
- **Manifest (`docs/manifest.md`, implemented in `manifest.mjs`):**
  - Top level: `protocol` "1.0.0"; `id` reverse-DNS, on the approved list; `short` `^[a-z][a-z0-9]{1,15}$`, unique among enabled plugins, all tool names start with `<short>_`; `version` semver (bump on every release); `title` 1–60; `description` ≤300; `publisher` `{id, key_id, name}`; `signature` ed25519 over JCS; optional `commands`, `scopes`, `routines`, `apps`; `needs` must be absent or `[]`.
  - `apps[]`: `id`, `title`, `description`, `entry` = `rox-app://<id>`, `mime` `text/x-nsh-tsx`, `sdk` "1", `fingerprint` `sha256:<hex of served source>`, `props` (JSON Schema subset, top-level object), `placement` (`full`, `inline`, or both), `inline` `{width, height, min_height?, max_height?, resizable?}`, `permissions`.
- **Permission keys** (`perms.rs` L71–90; unknown keys refused): `tools` (own names, ≤64); `open` `{apps (own ids, ≤16), external (https origins, ≤8)}`; `attach` (scope names, ≤16); `pick_file` `{extensions, max_bytes ≤50 MiB, multiple}`; `storage` `{quota_bytes ≤10 MiB}` (default 1 MiB); `copy` (bool); `preview` `{max_bytes ≤8 MiB}`. A method not granted is absent (`undefined`), not failing.
- **Bridge methods** (`docs/bridge.md`): `rox.props`, `rox.app`, `rox.viewport`, `rox.fit` (always); `rox.ticket.title` (always); `rox.call` (`tools`); `rox.open({app, props?, ticket?})` (`open.apps`, no prompt) or `rox.open({url})` (`open.external`, after consent); `rox.attach` (`attach`, after consent); `rox.pickFile` (`pick_file`; returns file handles, `read()` gives base64); `rox.storage.get/set/remove/keys` (`storage`); `rox.copy` (`copy`); `rox.preview` (`preview`).
- **Storage isolation:** per app `<plugins>/<plugin>/apps/<app>/storage.json` (`storage.rs` L39–46). Keys match `^[A-Za-z0-9._:-]+$`, ≤128 chars; values ≤64 KiB; ≤1000 keys (L112–117). The app never names a path.
- **Links:** `rox://app/<plugin id>/<app>?ticket=…&props=…`; ≤2048 chars; props in the link ≤1024 bytes (BIR `app_link` L603–621). An OS link asks for a dialog.
- **Backend reach:** only through `rox.call` to plugin tools. The plugin process reaches what it wants (BIR reaches the Buwiz server), and the protocol's guarantees H1–H13 (spec 15.1) cover the app sandbox, not the plugin process. **INFERENCE** from `plugins.mjs:157`.
- **Auth and token model:**
  1. Host token `X-Rox-Host`: 32 random bytes in `<data>/host-token`, mode 0600 (`routes.mjs` header). It authorizes `/v1/host/*` only, so it can open sessions but cannot call tools.
  2. Plugin key: ed25519 seed per install, in Keychain, provisioned over stdin (`keystore.mjs` header).
  3. Session key Ks per open, certified by the plugin (≤8 h).
  4. Each call signed by Ks, with nonce and timestamp.
  5. The plugin must authorize every subject itself (spec P1; `docs/security.md`). Tickets are random and the subject map stays with the plugin (P2, P3).
- **Limits** (`docs/bridge.md`, `manifest.mjs` LIMITS): args 256 KiB; result 1 MiB; 8 calls in flight; 20 calls per second; bridge timeout 30 s, broker to plugin 120 s, resolve 10 s, provision/session.open/uninstall 5 s; app source 512 KiB; app load 10 s; per JS call 2 s; heap 256 MB; stack 4 MB; routine `every_s` 60–86400.

**Cross-plugin consequences (CONFIRMED):** a separate Books plugin has no supported direct path to a BIR return. Its options are (i) the model calls both plugins, which puts data in model context; (ii) a user-clicked link or card, which needs a BIR ticket that only BIR issues (`tickets.rs` L215); or (iii) a shared Buwiz backend that both plugins call with their own credentials, which v1 does not mediate. Routine `reads` are read-only and for routines, not apps.

**Recommendation (INFERENCE):** for a first vertical slice that opens a BIR return from Books with a ticket, option (a) is the only path that uses supported v1 primitives today. Option (b) becomes sensible once Books must stand alone, or when BIR's failure domain and release cadence matter. Its handoff needs a shared backend design or a new Rox mechanism. The choice also depends on where ledger data lives (owner decision, below).

### 10. Discrepancies, risks, unknowns, owner decisions

**Discrepancies with the brief**
- The brief's BIR plugin path is absent. The actual plugin lives in `reverse-engineer-ebir-forms/bir`, and the installed broker is the Grok Shell bundle, not `rox/server`.
- Three `bir-core` trees diverge: the live plugin path-depends on `reverse-engineer-ebir-forms/bir/crates/bir-core` (`bir-shell/Cargo.toml` L84–85). Diffs against buwiz-forms (92 entries) and buwiz-oss (82) are CONFIRMED. Which tree is canonical is for the Forms track.
- `OSS/buwiz-forms` `integrations/opengrok/bir` is a separate OpenGrok plugin (`bir-mcp`), not the Rox plugin (CONFIRMED, README L1–20).
- The protocol spec (`drafts/rox-mini-app-protocol-v1.md`) is git-ignored (`.gitignore` L9) and untracked. The SDK docs cite it; it exists only on this machine.

**Risks and observations**
- Plugin-side denials reach apps as `tool_error`, not `permission_denied` (`sessions.mjs` L300). Possibly a gap against the spec's intent (see section 5, stage 7).
- BIR's ticket-less app tools reach catalogs, the Buwiz account, app setup, and lists across taxpayers, with rows carrying tickets (`app_tools.rs` header L1–30). This is by design. A Books list tool must enforce client scope itself.
- Two enabled BIR routines write BIR data every 300 s without a prompt, limited to listed tools (`bir_confirm_filing`, `bir_record_payment`) and Gmail reads. Any Books auto-write should follow the same `writes` rule (spec P6).
- Rox stores taxpayer display names in clear text in `mini-v1.json` (attachment and pin titles). H10 forbids identifiers, not names; **INFERENCE** on privacy impact.
- The plugin's DB key is read from a file via env (`BIR_NO_KEYCHAIN=1`); the Keychain is bypassed for this install (CONFIRMED env; storage posture INFERENCE).
- The BIR manifest `version` (2.6.3, `manifest.rs` L30) is independent of the crate version (`bir-mini-app --version` prints 0.1.0). A bump is required for any update to install.
- The local Spin process's argument list exposes a credentialed database URL (not reproduced).
